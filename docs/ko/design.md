# strata — 설계

> **상태: 초안 0.1 · 2026-10-14 갱신.** 이 문서는 [`docs/en/design.md`](../en/design.md) 의 한국어 번역이다. 정본은 영어
> 원본이고, 원본이 바뀌면 `tools/i18n_check.py` 가 이 번역을 낡은 것으로 표시한다.

## 1. strata 는 무엇인가

strata 는 저장소를 **AI 에이전트가 만드는, 층을 이루고 승인을 거치는 문서의 운영 체계**로 바꾸는
Claude Code 플러그인이다. 예를 들어 사업 기획이 제품 명세를 제약하고, 제품 명세가 다시 개발 기획을
제약하는 프로젝트다.

하는 일은 넷이다.

1. **층을 경로로 지킨다.** 모든 문서는 층(현재 · 이력 · 근거 …) 하나에 속하고, 층마다 쓰기 모드가
   있다. 그 모드를 깨는 쓰기를 훅이 막는다.
2. **상한이 있는 사이클을 돌린다.** 사이클은 여러 에이전트가 차례로 일하는 실행(예: 작성자 → 검토자 →
   판정자)이고, 자기 폴더 안에 *제안*을 만든다. 단계 순서 · 라운드 상한 · 질의 예산은 에이전트가 아니라
   상태 기계가 센다.
3. **게이트에는 사람이 선다.** 제안은 답할 차례인 사람이 답한 뒤에만 사이클 폴더 밖으로 나가고, 그 답은
   원문 그대로 파일로 남는다. 답 파일이 없으면 승인도 없다.
4. **추가 전용 기록을 남긴다.** 결정 · 실행 기록 · 상향 보고는 덧붙이기만 한다. 그래서 「왜 이렇게
   됐나」에는 언제나 답이 있다.

### 하지 않는 것

- **보안 경계가 아니다.** 훅은 사고를 막는다. 넘을 수 없는 선은 사람의 행위다 — 게이트에 답하기, 대화
  열기, 풀 리퀘스트 병합.
- **공유 작업 트리 조율기가 아니다.** strata 는 대화마다 워크트리 하나, 합치기는 풀 리퀘스트라고 본다.
  대화 사이의 조율은 나중에 붙일 수 있는 선택 모듈이다(§ 12, M6).
- **코드에 도메인 지식이 없다.** 트랙 이름 · 문서 타입 · 절 제목 · 역할 · 증거 태그는 프로젝트
  매니페스트의 데이터다. 코드는 어떤 프로젝트의 어휘도 담지 않는다.
- **코드 생성기가 아니다.** strata 는 문서와 기획을 다스린다. 구현 작업을 사이클로 추적할 수는 있지만,
  애플리케이션 코드는 쓰지 않는다.

## 2. 출발점과 바뀐 것

strata 는 문서가 먼저인 앞선 제품 프로젝트를 위해 처음 만든 운영 층을 백지에서 다시 쓴 것이다. 그
프로젝트는 2026-09~10 에 트랙 셋(사업 기획 → 제품 기획 → 개발)을 스킬 15 · 에이전트 17 · 도구 약 6만 줄로
돌렸다.

**원리**는 그대로 옮겼다(§ 3). **코드**는 옮기지 않았고, 그 이유는 앞선 프로젝트 안에서 잰 것이다.

| 앞선 프로젝트에서 배운 것 | strata 규칙 |
| --- | --- |
| 트랙 폴더 이름이 도구 파일 23개에 박혀 있었다. 트랙 이름만 바꾸니 로더 역할 18개 중 17개가 거절했고, ID 발급기는 조용히 틀린 값을 냈다. | 모든 구조는 매니페스트에서 온다. 고정물의 트랙 이름이 코드에 나오면 검사 시험이 실패한다(§ 11). |
| 공용 라이브러리가 마크다운 파일의 **한국어 절 제목**으로 설정을 찾았다. | 매니페스트는 영어 키를 쓰는 TOML 이다. 사람 말(제목 · 표시 이름)은 매니페스트의 *값*이다. |
| 설정 32항목 가운데 도구가 실제로 읽는 것은 14항목이었고, 나머지는 산문이었다. | 매니페스트의 모든 키는 스키마 항목과 읽는 쪽이 있다. 없으면 모르는 키로 거절한다. |
| 사이클 세 종류(정련 · 명세 · 개발 기획)가 같은 모양의 상태 기계를 저마다 따로 가졌다. | 사이클 엔진은 하나다. 사이클 종류는 매니페스트에 선언한다(§ 6). |
| 대화 여럿이 작업 트리 하나를 나눠 써서 레인 · 잠금 가드가 있었다. 그 프로젝트는 뒤에 대화마다 워크트리로 옮겼다. | 워크트리 + 풀 리퀘스트를 전제로 한다. 코어에는 레인 · 잠금 가드가 없다. |
| 조율 도구가 운영 기기 한 대(launchd · 로컬 수신함)를 전제했다. | 조율은 코어 밖이다. 붙인다면 Claude Code 의 기본 세션 기능 위에 만든다. |
| 키워드 일치만으로 문맥 순위를 매기니 얇은 현행 층이 두꺼운 아카이브에 밀렸다. 시험 질의 16건의 상위 8위 가운데 현행 기획은 6% 뿐이었고, 32% 는 사이클 사본, 34% 는 중복이었다. | 문맥 순위에 층 가중치를 곱하고, 중복을 걷고, 끝난 사이클은 기본으로 뺀다(§ 8). |

## 3. 원리

strata 가 지키려고 있는 규칙이다. 하나하나가 먼저 문장이고, 구현은 그다음이다.

- **P1 — 세 층을 경로로 지킨다.** *현재* 문서는 살아있고 사이클로 고친다. *이력*(결정)은 추가 전용이다.
  *근거*(조사 · 검토)는 쓰는 순간 시점 고정이다. 층마다 모드를 훅이 강제한다.
- **P2 — 경로가 곧 게이트다.** 사이클은 자기 폴더 안에만 쓴다. 폴더 밖으로 올리는 것은 원문 답 파일이
  뒷받침하는 승인 뒤에만 한다.
- **P3 — 작성자는 자기를 검토하지 않는다.** 작성자 · 검토자 · 판정자는 서로 다른 에이전트다. 에이전트는
  자기 역할이 읽어도 되는 파일만 받는다.
- **P4 — 상한은 기계가 센다.** 단계 전이 · 라운드 · 질의 예산은 사이클 엔진이 센다. 에이전트가 스스로
  멈추리라고 믿지 않는다.
- **P5 — 근거에는 태그를 단다.** 핵심 주장에는 매니페스트가 선언한 증거 태그를 단다. 수치와 법조문은
  지어내지 않는다.
- **P6 — 아래 층은 위로 보고하고, 덮어쓰지 않는다.** 위 층의 변경이 필요한 아래 사이클은 등록부에
  항목을 올린다. 결정은 위 층 담당자가 새 결정 기록으로 한다.
- **P7 — 검증자는 믿지 않고 다시 만든다.** 검증 단계는 작성자의 보고를 읽는 대신 증거를 다시 만든다
  (예: 바뀌기 전에 실패하는 시험).
- **P8 — 역할은 먼저 적고, 그다음에 막는다.** 선언된 역할은 먼저 역할 밖 쓰기의 그림자 장부를 남긴다.
  막는 것은 나중에 명시적으로 고른다.
- **P9 — 체계가 자기를 잰다.** 죽은 예외는 실패다. 이식성은 시험이다. 운영 규칙도 다른 산출물처럼
  평가하고 고칠 수 있다.

## 4. 개념

| 용어 | 뜻 |
| --- | --- |
| **매니페스트** | 사용자 저장소의 `.strata/strata.toml`. 프로젝트마다 다른 것을 모두 선언한다. |
| **트랙** | 자기 폴더를 가진 작업 단계(예: `business` · `product`). 트랙은 사람이 열고 닫는다. |
| **층** | 쓰기 모드 하나를 공유하는 경로 묶음(§ 5). 층은 트랙을 가로지른다. |
| **문서 타입** | 한 종류의 문서가 갖춰야 할 프런트매터 키와 절. |
| **사이클** | 자기 폴더 안에 제안을 만드는, 상한이 있는 다중 에이전트 실행. 종류 · 단계 · 라운드 · 상태 파일을 가진다. |
| **단계** | 사이클의 한 단계. 에이전트 역할 하나가 맡는다. |
| **게이트** | 사람이 답해야 하는 자리. 답은 사이클의 `inputs/` 에 원문 그대로 남는다. |
| **역할** | 사람의 역할(예: `planner` · `reviewer` · `owner`). 역할은 게이트를 맡고 쓰기 범위를 가진다. |
| **등록부** | 상향 보고나 열린 쟁점의 추가 전용 목록. 자기 ID 접두를 가진다. |
| **기록** | 추가 전용 실행 기록(`.strata/records/YYYY-MM.md`). |
| **증거 태그** | `[measured]` · `[assumed]` 같은 표지. 참조 규칙과 함께 매니페스트에 선언한다. |
| **접근 범위** | 사이클 단계 하나가 읽고 쓸 수 있는 것. 매니페스트에 단계마다 선언한다(§ 8.1). |
| **절 색인** | 마크다운 문서를 제목 수준별 절로 나눈 것. 질의와 대조해 점수를 매기고 문맥을 고른다(§ 8.2). |
| **변경 파일** | 문서 하나에 대한 제안 변경 하나. 사이클의 `changes/` 폴더에 있고, 승인 뒤에만 반영한다(§ 7.2). |
| **시작 안내** | strata 프로젝트에서 대화가 시작될 때 찍히는 짧은 길잡이(§ 7.3). |

## 5. 층과 경계

### 5.1 층 모드

| 모드 | 새로 만들기 | 부분 수정 | 통째 덮어쓰기(Write) | 삭제 |
| --- | --- | --- | --- | --- |
| `immutable`(불변) | 안 됨 | 안 됨 | 안 됨 | 안 됨 |
| `frozen`(시점 고정) | 됨 | 안 됨 | 안 됨 | 안 됨 |
| `append-only`(추가 전용) | 됨 | 됨¹ | 안 됨 | 안 됨 |
| `living`(살아있는) | 됨 | 됨 | 고정 상태가 아닐 때만² | 고정 상태가 아닐 때만² |
| `scratch`(작업장) | 됨 | 됨 | 됨 | 됨 |

¹ 기록을 `superseded` 로 표시할 수 있도록 부분 수정은 허용한다. 본문이 바뀌지 않았는지는 사이클 엔진과
  검증기가 본다.
² 프런트매터 `status` 가 `frozen_statuses`(예: `accepted`)에 든 살아있는 문서는 덮어쓰거나 지울 수
  없다. 부분 수정은 여전히 된다.

### 5.2 경계와 강제 수단

| 경계 | 무엇을 지키나 | 강제 | 성격 |
| --- | --- | --- | --- |
| **층** | 모든 층의 모드(§ 5.1) | `layer_guard` 훅 | 막는다 |
| **트랙** | 닫힌 트랙에는 쓰지 않는다 | `layer_guard` 훅 | 막는다 |
| **사이클** | 승인 전 제안은 사이클 폴더 안에 머문다 | 로더의 `writable_paths` + 사이클 엔진 + 반영 사전 점검 | 계약 |
| **역할** | 역할 밖 쓰기가 보인다 | `role_shadow` 훅 | 적기만 한다 |

사이클 경계가 계약인 것은 일부러다. 훅은 서브에이전트와 그 호출자를 가려내지 못하고, 같은 대화가 상태
파일을 고칠 수 있다. 넘을 수 없는 선은 승인 그 자체, 곧 사람이 답하는 일이다.

### 5.3 가드 동작 규칙

앞선 프로젝트 가드의 회귀에서 그대로 가져왔고, 첫날부터 시험한다.

- **매니페스트가 없으면 아무것도 하지 않는다.** `.strata/strata.toml` 이 없는 저장소에서는 모든 훅이
  0 으로 끝난다.
- **실행 기록은 언제나 추가 전용이다.** `.strata/records/**` 는 모든 프로젝트에서, 매니페스트가 선언한
  어느 층보다 먼저 추가 전용 층으로 판정한다.
- **닫힌 쪽으로 실패하되, 고칠 길은 막지 않는다.** 매니페스트가 있는데 읽을 수 없으면 보호 구역 쓰기를
  막는다. 매니페스트를 고칠 수 있도록 `.strata/**` 는 계속 쓸 수 있다.
- **프로젝트 밖은 판정하지 않는다.** 저장소 루트 밖 경로는 통과한다.
- **상대 경로는 도구의 작업 폴더 기준으로 푼다.** Bash 명령 안의 `cd` 도 따라간다.
- **대소문자를 가리지 않는 파일시스템을 다룬다.** macOS 와 Windows 에서 `Docs/x.md` 와 `docs/x.md` 는
  같은 파일이다.
- **Bash 는 보수적으로 판정한다.** 리다이렉션과 흔한 쓰기 명령(`rm` · `mv` · `cp` · `tee` · `sed -i` ·
  `truncate` · `touch` · `dd` · `git rm` · `git mv` · `find -delete`)을 해석한다. 헤어독 본문은 건너뛴다.
  인터프리터에 넘긴 코드 · `eval` · `$` 가 든 낱말은 해석하지 않으며, 문서에도 그렇게 적는다.
- **통째 삭제는 안을 본다.** 폴더의 `rm -r` 이나 `mv` 는 그 아래 파일 하나라도 막힐 것이면 막는다.
  프로젝트 루트를 품은 폴더의 삭제는 언제나 막는다.
- **해석하지 못한 명령은 이름을 댄 것만 막는다.** 토큰화에 실패하면, 명령 글자에 보호 구역(층 경로의
  앞부분이나 닫힌 트랙)이 들어 있을 때만 막는다.
- **우회는 명시적이다.** Claude Code 를 띄운 환경에 `STRATA_GUARD_BYPASS=1`. 모든 차단 메시지가 우회
  방법과 쓸 때를 함께 알린다.

## 6. 매니페스트

매니페스트는 TOML 이다(파이썬 표준 `tomllib` 로 읽는다). 키는 영어이고, 값은 어느 언어든 된다. 모르는
키는 오류다.

```toml
[project]
name = "acme"
language = "en"            # 훅 · 도구 메시지 언어: "en" | "ko"
schema = 1

[[tracks]]
id = "business"
path = "tracks/business"
open = true

[[tracks]]
id = "product"
path = "tracks/product"
open = false

[[layers]]
id = "evidence"
mode = "frozen"
paths = ["tracks/*/archive/research/**", "tracks/*/archive/reviews/**"]

[[layers]]
id = "history"
mode = "append-only"
paths = ["tracks/*/decisions/**"]

[[layers]]
id = "current"
mode = "living"
paths = ["tracks/*/plan/**", "tracks/*/specs/**"]

[[layers]]
id = "source"
mode = "immutable"
paths = ["docs/originals/**"]

[documents]
frozen_statuses = ["accepted", "done", "superseded"]

[[documents.types]]
id = "decision"
frontmatter = ["type", "id", "title", "date", "status"]
sections = ["Context", "Decision", "Consequences", "Review conditions"]

[[evidence.tags]]
tag = "measured"
label = "[measured]"
reference = "P-\\d+"

[[cycles]]
id = "refine"
prefix = "RF"
track = "business"
folder = "archive/refinements"
steps = ["intake", "analysis", "plan", "critique", "verdict"]
max_rounds = 3
asks_per_round = 1
asks_total = 2
retry_to = ["analysis", "plan"]
approver = "owner"

[[roles]]
id = "owner"
writes = ["**"]
gates = ["refine.approve"]

[[registers]]
id = "upward"
prefix = "UP"
path = "tracks/business/registers/upward.md"
```

**트랙이 열렸는지는 매니페스트 필드다.** 트랙을 여는 것은 사람의 결정이므로 검토된 차이로 보여야 한다.
따로 둔 상태 파일은 지워지거나 깨질 수 있는 것을 하나 더 늘린다. 앞선 프로젝트에서는 깨진 상태 파일 하나가
트랙 가드 전부를 통과시킨 적이 있다.

사이클 상태는 매니페스트에 **두지 않는다.** 각 사이클의 폴더에 살고, 기록 한 줄을 남기는
`strata cycle` 명령으로만 바뀐다(M3).

층은 **선언한 순서로 맞춰 보고, 처음 맞는 것이 이긴다.** 어느 층에도 맞지 않는 경로는 판정하지 않는다.
매니페스트 파일(`.strata/strata.toml`) 자체는 언제나 쓸 수 있다.

## 7. 문서의 일생

### 7.1 문서가 사는 자리

모든 것은 프로젝트 git 저장소 안의 마크다운 파일이다. 데이터베이스는 없다.

| 무엇 | 어디 | 흔한 층 모드 | 쓰는 쪽 |
| --- | --- | --- | --- |
| 사이클 작업 파일 | `{track}/{사이클 폴더}/{접두}-{nnn}-{slug}/` | `scratch` | 단계마다 그 단계의 에이전트가 접근 범위 안에서 |
| 사이클 상태 | `{cycle}/.state.json` | `scratch` | `strata cycle` 만 |
| 근거 원문과 게이트 답 | `{cycle}/inputs/` | `frozen` | 스킬이 원문 그대로, 그것을 쓰는 단계 전에 |
| 제안 변경 | `{cycle}/changes/` | `scratch` | 기획 단계 |
| 결정 초안 | `{cycle}/decisions/` | `scratch` | 기획 단계 |
| 현행 문서 | 예: `{track}/plan/` | `living` | `strata cycle apply` |
| 결정 기록 | 예: `{track}/decisions/` | `append-only` | `strata cycle apply` |
| 근거 | 예: `{track}/archive/research/` | `frozen` | 조사 단계가 한 번 |
| 등록부 | `[[registers]]` 에 선언 | `append-only` | `strata register add` 또는 `strata cycle apply` |
| 실행 기록 | `.strata/records/YYYY-MM.md` | `append-only` | `strata record` |

- **사이클 폴더는 사이클이 닫힌 뒤에도 남는다.** 그 사이클이 만든 결정 기록의 근거가 된다.
- **작업장 폴더 안에서도 `inputs/` 는 시점 고정이다.** 사이클의 작업장 층보다 앞에 `inputs` 층을 선언한다.
  처음 맞는 층이 이기므로(§ 6), 원문 답은 나중에 고칠 수 없다.
- **상태는 JSON 이다.** 표준 라이브러리는 TOML 을 읽을 수는 있지만 쓸 수는 없다.
- 「쓰는 쪽」 칸은 일부가 계약이다. 층 모드가 금지하는 것은 가드가 막지만, 사이클 밖의 에이전트가 살아있는
  문서를 고치는 것은 막지 않는다. 그런 수정은 git 에 보이고, M5 부터는 역할 장부에도 남는다.

### 7.2 반영: 승인된 제안이 문서에 닿는 길

사이클은 제안을 **변경 파일**로 낸다. 대상 문서마다 하나씩 `{cycle}/changes/` 에 둔다.

```markdown
---
target: tracks/business/plan/04-launch.md
action: modify          # create | modify | append | retire
---

시범 지역을 요청에 적힌 구역으로 좁힌다.

<!-- strata:current -->
The trial runs in one district.
<!-- strata:revised -->
The trial runs in two neighbouring districts.
<!-- strata:end -->
```

| 동작 | 뜻 |
| --- | --- |
| `modify` | 현행 · 개정 짝이 하나 이상. 현행 블록은 대상 문서에 정확히 한 번 나와야 한다. |
| `create` | 개정 블록이 새 파일 전체다. 대상이 없어야 한다. |
| `append` | 개정 블록을 끝에 덧붙인다. 등록부와 추가 전용 문서에 쓴다. |
| `retire` | 대상의 상태를 `[documents] retired_status` 로 바꾼다. 본문은 바뀌지 않는다. |

표지는 HTML 주석이라 변경 파일은 어느 언어로든 자연스럽게 읽히고, 제목 글자를 파싱하지 않는다.

**결정 기록**은 번호 없이 `{cycle}/decisions/` 에 초안으로 쓴다. 반영할 때 대상 폴더의 다음 빈 ID 를 주고
`based_on: {사이클 ID}` 를 더한다.

`strata cycle apply --id RF-001` 은 세 단계로 돈다.

1. **승인을 확인한다.** 사이클 상태가 `approved` 여야 하고, 승인 답이 `inputs/` 에 있으며 승인 역할을
   밝혀야 한다.
2. **쓰기 전에 모든 변경을 미리 점검한다.** 대상은 동작이 요구하는 대로 있거나 없어야 한다. 모든 현행
   블록이 여전히 정확히 한 번 맞아야 한다. 동작이 대상의 층 모드에서 허용돼야 하므로, 이미 있는 `immutable`
   · `frozen` 파일은 절대 건드리지 않는다. 결과 문서는 모두 메모리에서 검증한다. 하나라도 실패하면 반영
   전체가 멈추고 아무것도 쓰지 않는다.
3. **쓰고, 기록한다.** 모든 변경을 쓰고, 결정 기록에 번호를 매겨 쓰고, 기록 한 줄을 붙이고, 상태를
   `applied` 로 바꾸고, 기획이 밝힌 하위 영향을 출력한다. 다음 사이클은 열지 않는다. 그것은 사람이 한다.

대상이 더 이상 맞지 않으면, 승인 뒤에 문서가 바뀐 것이다. 사이클은 사람에게 돌아가고, 도구는 그 차이를
돌아서 합치지 않는다.

「일부만」 · 「고쳐서」 · 「나중에」 라고 답한 승인은 승인이 아니다. 스킬은 그 답을 원문 그대로 남기고, 새
사이클을 열지 닫을지를 묻는다. 일부만 반영하는 일은 없다.

**왜 에이전트가 아니라 도구인가.** 앞선 프로젝트에서는 에이전트가 변경 파일을 손으로 반영했고, 기획과 변경
파일이 어긋나는 것을 잡는 규칙을 따로 둬야 했다. 정확한 문자열 짝을 적용하는 도구는 반영 결과를 승인한
그대로 바이트 단위까지 같게 만들고, 어긋난 대상을 조용한 병합이 아니라 멈춤으로 바꾼다.

### 7.3 시작 안내: 대화가 길을 찾는 법

매니페스트가 있는 프로젝트에서 대화가 시작되면, `SessionStart` 훅이 짧은 안내를 찍는다.

- 프로젝트 이름과 열린 트랙
- 열린 사이클과 그 단계, 답할 차례 — 답을 기다리는지, 승인돼 반영을 기다리는지(M3 부터)
- 먼저 읽을 문서(`[context] start`)
- 쓸 수 있는 strata 스킬

안내는 `[context] brief_chars`(기본 1,500자)를 넘지 않는다. 파일을 통째로 싣지 않고 이름만 대며,
`project.language` 로 쓴다. 매니페스트가 없으면 아무것도 찍지 않는다.

### 7.4 문서 일생용 매니페스트 키 (계획 — M2 · M3)

§ 8.3 과 같이, 아래 키는 **아직 로더가 받지 않는다.**

```toml
[documents]
retired_status = "superseded"          # `retire` 변경이 바꾸는 상태

[context]
start = ["README.md", "tracks/business/plan/index.md"]   # 시작 안내에 이름이 나온다
brief_chars = 1500

[[cycles]]
id = "refine"
# ...
decisions = { folder = "decisions", prefix = "D" }   # 반영이 결정 기록에 번호를 매기는 자리 · 없으면 결정 기록 없음
```

## 8. 문맥 선택

에이전트는 큰 문서를 통째로 읽지 않아야 하고, 읽는 것은 층(P1)과 작성자 · 검토자 분리(P3)를 지켜야
한다. strata 는 문맥을 두 겹으로 고른다. 사이클 단계마다 고정된 범위가 있고, 그 범위 안에서 점수로
찾는다.

### 8.1 단계별 접근 범위

사이클 단계마다 읽는 것과 쓰는 것을 선언한다. 로더는 그것을 에이전트에게 목록 둘로 돌려준다. 순서대로
읽을 `files_to_read` 와 쓸 수 있는 `writable_paths` 다. 목록에 없는 것은 읽지 않고, 제외가 포함보다
앞선다.

```toml
[[cycles.access]]
step = "critique"
reads = ["{track}/plan/**", "{cycle}/request.md", "{cycle}/plan.md", "{cycle}/changes/**"]
excludes = ["{cycle}/verdict.md"]
writes = ["{cycle}/critique.md"]
```

- `{cycle}` 은 그 사이클의 폴더, `{track}` 은 그 트랙의 폴더다. 다른 자리표시자는 오류다.
- `writes` 는 `{cycle}` 안에 있어야 한다. P2(「경로가 곧 게이트다」)가 에이전트에게 닿는 자리가 여기다.
- 접근 항목이 없는 단계는 모든 것을 주는 대신 로더가 거절한다.
- 로더는 무엇을 뺐는지 알린다. 그래서 에이전트는 형제 산출물이 있다는 것을 알되 찾아 읽지 않는다.

### 8.2 점수 기반 검색

자기 범위 안에서 필요한 부분은 `strata context` 로 찾는다. 문서는 절 단위(기본 H2 · H3)로 색인한다.
질의는 절마다 점수를 매기고, 신호마다 질의 토큰당 한 번만 세므로 반복이 점수를 부풀리지 않는다.

| 신호 | 기본 가중치 |
| --- | --- |
| 제목 토큰 정확 일치 | 10 |
| 파일 경로 조각 | 8 |
| 인용 경로 조각(절이 언급한 경로) | 6 |
| 제목 토큰 부분 일치 | 5 |
| 프런트매터 `description` | 4 |
| 본문 낱말 | 2 |
| 경로 모양 질의 ↔ 인용 경로 끝부분, 또는 ↔ 프런트매터 `sources` 글롭 | 6 |

합계에 다시 곱한다.

- 파일이 속한 층의 **층 가중치**(`[[layers]] weight`, 기본 1.0). 같은 낱말이라도 현행 층이 아카이브 사본보다
  위에 온다.
- 파일 프런트매터 상태의 **상태 가중치**(`[documents] status_weights`, 예: `superseded = 0.5`).

그 밖의 규칙.

- **중복은 하나로 접는다.** 제목과 본문이 같은 절은 순위가 가장 높은 하나만 남긴다.
- **끝난 사이클과 기록은 기본으로 뺀다.** 「끝남」은 경로가 아니라 사이클 엔진의 상태로 가른다. 선택지로
  넣을 수 있고, `select:` 로 지목한 질의는 언제나 동작한다. 사이클 엔진(M3)이 생기기 전에는 끝난 사이클이
  없는 것으로 본다.
- **큰 절은 조각낸다.** 빈 줄이나 표 행에서 끊어, 거대한 기록 표 하나가 예산을 혼자 먹지 못하게 한다.
- **동점은 층 가중치, 그다음 경로로 가른다.** 결과는 결정적이다.
- **색인은 호출마다 메모리에서 만든다.** 캐시를 쓰지 않으므로 색인이 낡을 일이 없다. 시험이 문서 500개
  고정물의 색인을 지연 예산 안에 만드는지 본다. 실제 프로젝트가 그 한도를 넘으면, 파일 크기와 수정 시각을
  열쇠로 한 `.strata/` 아래 캐시가 계획된 대안이다.
- **제외가 가린 것은 상위 결과에 들었을 때만 알린다.** 그래야 알림이 의미를 잃지 않는다.

질의 형식.

| 형식 | 뜻 |
| --- | --- |
| `낱말 낱말` | 선택 토큰. 함께 채점한다 |
| `+낱말 다른것` | `+낱말` 은 반드시 나와야 하고, 나머지는 채점한다 |
| `select:경로#제목, 경로2` | 지목한 절이나 파일. 채점하지 않는다 |

의도한 흐름은 세 단계다. 본문 없이 점수와 크기만 붙은 후보 목록을 보고, 에이전트가 고르고, 고른 절만
바이트 예산 안에서 주입한다.

**언어.** 토큰화는 `project.language` 로 고른다. 한국어는 붙어 있는 낱말이 이어 쓴 꼴과도 맞고
(`접수 상태` ↔ `접수상태`), 긴 한글 토큰은 띄어 쓰든 붙여 쓰든 맞는다. 언어마다 규칙은 그 언어 고정물의
골든 질의로 시험한다.

**재는 법.** 고정물마다 골든 질의와, 상위 결과에 반드시 나와야 할 절을 둔다. 순위 변경이 그중 하나를
떨어뜨리면 시험 묶음이 실패한다.

### 8.3 문맥 선택용 매니페스트 키 (계획 — M2)

아래 키는 설계의 일부이고, **아직 로더가 받지 않는다.** M2 를 만들 때 스키마 · 시험 · § 6 에 함께 넣는다.

```toml
[[layers]]
id = "current"
mode = "living"
paths = ["tracks/*/plan/**"]
weight = 1.5                 # 문맥 순위 배수, 기본 1.0

[documents]
status_weights = { superseded = 0.5 }

[context]
section_levels = [2, 3]      # 절을 시작하는 제목 수준
chunk_bytes = 6000           # 이 값의 두 배보다 큰 절은 조각낸다
budget_bytes = 40000         # 호출 한 번에 주입하는 최대치
limit = 12                   # 기본 결과 수
exclude = [".strata/records/**"]   # 요청하지 않으면 뺀다

[[cycles.access]]            # 단계마다 하나 · § 8.1 참조
step = "analysis"
reads = ["{track}/plan/**", "{cycle}/inputs/**", "{cycle}/request.md"]
writes = ["{cycle}/analysis.md"]
```

```
docs/en/, docs/ko/       문서. 영어 원본과 한국어 번역
```

실행 조건: **Python 3.11 이상**(`tomllib` 때문), 표준 라이브러리만.

이 배치가 기대는 패키징 사실(Claude Code 플러그인 문서, 2026-10-14 확인):

- `.claude-plugin/marketplace.json` 이 플러그인을 `"source": "."` 로 올리므로 저장소 루트가 곧
  플러그인이다. 설치는 `claude plugin marketplace add radiostart/strata` 와
  `claude plugin install strata@strata`.
- **최상위 `bin/` 을 두지 않는다.** 플러그인의 `bin/` 은 Bash 도구의 `PATH` 에 올라가지만, claude.ai 와
  Cowork 의 설치도 막는다. 명령줄은 `scripts/` 에 두고 스킬은 전체 경로로 부른다.
- `${CLAUDE_PLUGIN_ROOT}` 는 스킬 · 명령 · 에이전트 마크다운과 `hooks.json` 에서 치환된다. Bash 도구
  안의 환경 변수로는 **없다.** 그래서 스킬은 치환된 경로를 명령마다 적는다.
- **`python3` 이 있다는 보장은 없다.** 훅은 Python 3.11+ 를 찾는 `hooks/run.sh` 를 거친다. 매니페스트가
  없는 프로젝트에서는 조용히 0 으로 끝난다. 매니페스트가 있는데 쓸 수 있는 Python 이 없으면, 파일 쓰기
  도구를 막고 고치는 법(Python 설치 또는 우회)을 알린다. Bash 명령은 막지 않고 경고만 한다. 모든 명령을
  막으면 Python 설치까지 막히기 때문이다.
- PreToolUse 훅은 종료 코드 2 로 막고, 그 stderr 가 Claude 에게 보인다.
- 저장소 루트의 `CLAUDE.md` 는 strata 를 개발하는 사람과 에이전트를 위한 것이다. Claude Code 는 플러그인
  사용자에게 이것을 맥락으로 싣지 않고, `claude plugin validate` 가 그것을 경고로 알리는데 의도한 대로다.
- 플러그인 스킬은 `/strata:<스킬>`, 에이전트는 `strata:<에이전트>` 로 부른다.

## 10. 언어 정책

| 산출물 | 언어 |
| --- | --- |
| 코드 · 식별자 · 주석 · 커밋 메시지 | 영어 |
| 스킬과 에이전트(`SKILL.md` · `agents/*.md`) | 영어. 모델은 사용자의 언어로 답한다. |
| 훅 · 도구 메시지 | 메시지 카탈로그. `project.language` 가 `en` 이나 `ko` 를 고르고, 없는 키는 `en` 으로 돌아간다. |
| 문서 | 영어 원본은 `docs/en/`. 한국어 번역은 `docs/ko/` 이고, 첫 줄이 원본 파일과 그 해시를 적은 표지다. 번역이 없거나 원본보다 오래되면 `tools/i18n_check.py` 가 실패한다. |
| README | `README.md`(영어)와 `README.ko.md`(한국어). 규칙은 문서와 같다. |
| 프로젝트 뼈대 | 언어마다 템플릿 한 벌. 제목과 표시 이름은 매니페스트의 값이라 파서는 언어에 기대지 않는다. |

## 11. 시험 규칙

- 표준 라이브러리 `unittest` — `python3 -m unittest discover -s tests`.
- **고정물은 언제나 둘 이상.** 모든 가드 · 엔진 시험은 트랙 이름과 언어가 서로 다른 고정 프로젝트 둘
  이상에서 돈다. 하나에서만 되는 동작은 결함이다.
- **코드에 어휘가 없다.** 검사 시험이 `strata/` · `hooks/` · `scripts/` 의 동작에 영향을 주는 문자열
  리터럴(독스트링 · 주석 제외)에서 고정물이 쓰는 트랙 ID · 폴더 이름 · 상태 · 단계 · 제목을 찾는다.
  하나라도 나오면 실패한다. 고정물 낱말은 strata 스키마 키와 겹치면 안 된다.
- **가드는 지연 시간도 시험한다.** 정한 예산보다 오래 걸리는 훅은 시험 묶음을 실패시킨다.
- **번역도 시험한다.** 시험 묶음이 `tools/i18n_check.py` 를 돌린다.

## 12. 로드맵

**끝난 것:** M0 과 M1. 지금 상태와 다음 이정표의 작업 목록은 [development.md](development.md) 에 있다.

| 이정표 | 범위 | 끝 조건 |
| --- | --- | --- |
| **M0 — 기반** | 매니페스트 로더와 스키마, 층 · 트랙 가드, 메시지 카탈로그, 번역 검사, 저장소 규약 | 가드 시험이 고정물 둘에서 통과 · 이 저장소에서 플러그인 설치 |
| **M1 — 기록과 검증** | `strata validate`(프런트매터 · 절 · 증거 태그), 추가 전용 기록, 등록부, `strata init` 뼈대, 얇은 스킬 `/strata:init` · `/strata:validate` · `/strata:status` | 뼈대로 만든 프로젝트가 두 언어 모두에서 깨끗이 검증된다 · 세 스킬이 그 프로젝트에서 동작한다 |
| **M2 — 문맥 선택** | 절 색인, 층 · 상태 가중치를 쓰는 점수 기반 검색, `strata context`, 단계별 접근 범위와 `files_to_read` · `writable_paths` 를 돌려주는 로더(§ 8), 트랙과 먼저 읽을 문서를 담은 시작 안내(§ 7.3), 얇은 스킬 `/strata:context` | 골든 질의가 두 고정물에서 통과 · 접근 항목이 없는 단계는 거절된다 · `/strata:context` 가 고정 프로젝트에서 순위 매긴 절을 돌려준다 |
| **M3 — 사이클 엔진** | `[[cycles]]` 에서 나오는 범용 상태 기계: 단계 · 라운드 · 질의 · 판정 · 답 파일 승인, 변경 파일과 사전 점검 · 결정 번호 매기기를 하는 `strata cycle apply`(§ 7.2), 시작 안내의 열린 사이클 | 사이클이 모든 hard-stop 사유에서 멈춘다 · 답 파일 없는 승인은 거절된다 · 어긋난 대상에 대한 반영은 아무것도 쓰지 않는다 |
| **M4 — 사이클 스킬과 에이전트** | 엔진으로 사이클을 모는 스킬, 그리고 로더에서 출발하는 범용 작성자 · 검토자 · 판정자 · 검증자 에이전트 | 고정 프로젝트에서 사이클 하나가 처음부터 끝까지 돈다 |
| **M5 — 역할과 게이트** | 역할 선언, 그림자 장부, 게이트 담당 | 역할 밖 쓰기가 장부에 나온다 · 게이트 답이 역할을 밝힌다 |
| **M6 — 조율(선택)** | 작업 항목 어댑터 계약과, Claude Code 기본 세션 위의 조율기 | 실제 둘째 프로젝트가 M0~M5 를 쓴 뒤에야 정의한다 |

**스킬은 자기 도구와 함께 나온다.** 명령 하나를 감싸기만 하는 스킬은 그 명령과 같은 이정표에 낸다. 그래서
이정표마다 사용자가 돌려 볼 수 있는 것이 남는다. 사이클을 모는 스킬과 그 스킬이 부르는 에이전트는 로더(M2)와
사이클 엔진(M3)을 기다린다. 그 둘이 없으면 사이클 스킬은 상한을 지시문으로 세고 에이전트 본문에 프로젝트
경로를 적어야 하는데, 그 둘이 P4 와 § 1 이 막는 것이다.
